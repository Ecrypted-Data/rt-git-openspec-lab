# Design

## Context

现有 `image_copy.py` 只有一次 `Path.iterdir()` 单层遍历：对每个 `is_file()` 且后缀属于 `SUPPORTED_EXTENSIONS` 的条目调用 `shutil.copy2` 并打印 `Copied <文件名>`，其余条目静默跳过。输出目录由调用方预先创建，脚本不负责创建。本次改动只增加统计与汇总输出，动机见 `proposal.md`，行为契约见 `specs/image-copy/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在同一次遍历中同时得到成功复制数与第一层被跳过的文件数，不额外扫描目录。
- 汇总行固定出现在所有逐文件日志之后，格式与数量语义按规格输出。

**Non-Goals:**

- 不改变输出目录的创建方式（创建输出目录属于另一个 Issue 的范围）。
- 不引入递归遍历、日志框架或第三方依赖。
- 不改变输出通道：汇总只写标准输出，不写文件，也不新增日志文件。

## Decisions

**在现有循环内累计计数，而不是复制完成后重新统计输出目录。**
输出目录可能事先已有同名或同类型文件，事后统计会把历史文件算进本次结果。在 `shutil.copy2` 成功后自增 `copied`，语义与"本次成功复制"一致，也避免第二次目录遍历。

**跳过计数放在 `else` 分支，只对第一层普通文件生效。**
现有循环的 `if` 已用 `path.is_file()` 过滤掉目录，因此 `else` 分支天然只统计第一层不受支持的普通文件，子目录及其内容本来就不会进入循环体。相比显式递归判断，这样不需要新增分支，也不会把子目录当成被跳过的文件。

**汇总在循环外无条件打印一次。**
放在循环后而不是 `finally`：输入目录不存在时由 `parser.error` 提前退出，按规格不应出现汇总行；正常流程（含零图片）都会走到循环末尾，一次调用即可满足"每次运行只输出一行汇总"。

**数量用 `len` 之外的独立变量维护。**
用两个整数计数器随遍历自增，不把匹配到的路径先收集成列表再取长度，额外内存为 O(1)；即使输入目录很大也不会因为统计而多占内存。

## Risks / Trade-offs

- [下游脚本按行解析标准输出时，末行新增内容可能影响既有断言] → 汇总行固定格式且只在末尾追加，既有逐文件日志的行内容与顺序不变；如需严格兼容可截取到倒数第二行。
- [统计口径与"复制成功"绑定，复制中途抛异常时不会打印汇总] → 与既有失败语义一致（异常直接上抛、非零退出），符合规格中"失败时的报错保持原样"。
- [扩展名判断复用了 `SUPPORTED_EXTENSIONS`，未来新增格式会自动同时影响复制与统计] → 这正是期望行为，两个口径保持一致，无需额外维护。
