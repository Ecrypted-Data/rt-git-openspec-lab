## Context

命令入口在确认输入目录有效后，直接将文件复制到指定输出路径。改动前的 `main` 上，输出目录必须预先存在，否则复制第一张图片时 `shutil.copy2` 抛出 `FileNotFoundError`（见 `proposal.md` 与 Issue #2 的复现步骤）。

## Goals / Non-Goals

- 让不存在的输出目录可直接作为参数。
- 保留支持的图片格式和现有命令行参数。

## Decisions

**先验证输入目录，再准备输出目录。** `parser.error` 在创建目录之前就返回，因此输入路径无效时不会留下空目录，正好满足 Issue 中"输入目录无效时不创建输出目录"这一条。

**使用标准库 `Path.mkdir(parents=True, exist_ok=True)` 完成目录创建。** `parents=True` 一次补齐缺失的父目录（如 `out/repro/new-output` 中的两个层级）；`exist_ok=True` 让输出目录已存在时直接跳过，无需额外分支判断，已存在目录上的复制行为因此与改动前一致。备选方案是逐级 `os.makedirs` 或先 `exists()` 再创建，前者等价但冗长，后者在并发或竞态下不如 `exist_ok` 可靠。

**不改动复制循环。** 目录准备完成后，逐个文件的复制、文件名保留与 `SUPPORTED_EXTENSIONS` 过滤都沿用现有实现，`notes.txt` 依然不会被复制。

## Risks / Trade-offs

对已存在的输出目录，检查复制后的文件名仍与原行为一致。

- [输出路径已被一个普通文件占用时，`mkdir` 抛 `FileExistsError`] → 与改动前复制阶段的失败语义一致（非零退出、不留下部分结果），Issue 未要求专门提示，本次不额外处理。
- [权限不足导致目录创建失败] → 异常在复制第一张图片之前就抛出，比原来"复制到一半才失败"更早暴露问题，不会留下半成品。
- [`exist_ok=True` 会掩盖"输出路径是文件"以外的其他已存在情况] → 除路径被文件占用外，其余已存在情形（空目录、已有同名图片）都是原本就支持的行为，不属于被掩盖的错误。
